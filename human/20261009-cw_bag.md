# 2026-10-09: One bag shape (columnwise thread 10) -- git files change once, stored formulas rewritten

The bag a formula reads, the bag a template reads, and the jsonball git and Raw Export write now
hold a quiz in one shape, the export's: `question` and `questions` (every question by its label)
where the bag said `qn` and `qns`. The record is `notes/decisions/20261008-columnwise.md`,
section 12, with every place the bag still departs from the export and why.

## Every hunt's git files change once

On the first write after the deploy, each hunt's files are rewritten in the new shape, all at once:

* every question, widgeting and column carries its `label` beside its `position`, and so does each
  of the library's widgets;
* each category carries its `label` and `title` beside its `position`;
* each quiz carries its `label`, and what a widgeting run once for the whole quiz came to sits
  beside the quiz's own fields (`playtesters: { status, value }`), no longer under `widgeteds`;
* the `.tsv` beside each grows the new columns.

Nothing is lost: the importer reads both shapes, for good.

## The deploy

The pull request is a **Serial Deploy (`bagshape`)**: it adds six backfills to `Backfills`, which
rewrite production's stored texts (widgets' formulas and input formulas, `liquidize` widgetings'
templates, columns' refs and templates, recap heads, tails and templates, and each templateable
text a quiz nominates). No schema change, so nothing to tighten; the ledger row is in
`notes/deploy.md`. Merge up to it, wait for `Backfills: every one has finished.`, then the rest.
Until the backfills finish, a stored formula still saying `qn` reads nothing, for a minute.

**The seeded butnot and ish widgets need nothing by hand**: the backfill rewrites them like any
widget, and a test holds the rewrite of the seeds as they stood before this thread
(`fixtures/seeds-2026-10-09.json`) to the seeds as they read now, character for character. If
production's library held an older wording of a seed, the rewrite still turns its
`qns[label = $$.qn.chains_to]` into the lookup. Worth one look after the deploy: the library's
`butnot_full` should read `(question.chains_to ? $lookup(questions, question.chains_to)).numnum_hint`.

**Before deploying**, one grep of production's raw export, expecting none:

* a widgeting **of the `quiz` tier** labelled `q1_preamble`, `recap_head`, `recap_tail`,
  `recap_template`, `templateable`, `locked` or `last_sortkey`, and a widgeting of either tier

## What the rewrite cannot reach

The rewrite is a heuristic (`src/models/before-october.ts`), and the Coach was fine with breaking
some formulas. It leaves these, each reading nothing (or a dash) until an author fixes it:

* **A failure read from the bag** (`question.dumdum.err.message`, `.err` anywhere): the bag no
  longer holds failures. The cell still shows its badge.
* **A column showing `qns`** (now `questions`) whose formula treated it as a list: `$count($)` must
  become `$count($.*)`, `$[0]` must become `$.*[0]`. Likewise a `template_from` reading `qns`.
* **A template reading the questions by position**: `qns.first`, `qns[0]`, `quiz.questions.last`
  become `questions.first` and the like, which read nothing on a keyed collection; use
  `{% assign list = questions | values %}{{ list.first.title }}`. And `qns.size` becomes
  `questions.size`, which now counts the archived too.
* **A formula over the hunt's `categories` by position** (`categories[0]`): it becomes
  `categories.*[0]`, which works; a column whose ref is `categories` and whose formula reads `$` as
  a list does not.
* **A formula or template reading an input of its own** (a widget whose input formula is not `$`,
  an `aibot` prompt) is left as it was, rightly: it reads the input's keys. An input formula that
  built `{ 'qn': qn }` becomes `{ 'qn': question }`, its key kept, so what reads it still works.
* **Prose** is never touched: only text inside Liquid tags and outputs, and formulas outside their
  strings and comments. The seeded `category_data` and `blurb` widgets' **descriptions** in
  production still say `qn.category_data.masie` and `{{ qn.title }}`; seeding does not update a
  row. An admin may paste the new ones from `src/models/seeds.ts`, or leave them.

`notes/examples/20261008-but_not_recap.json` (gitignored, in the main checkout) needs no rewrite:
the importer reads it as it is, old grammar, old bag words and all, as every older export.
