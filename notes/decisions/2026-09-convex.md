# Storage: Convex (Sept 2026)

**Decision.** Quizzes, hunts and everything in them live in **Convex** (`convex`, pinned exact):
a hosted database whose schema and functions are TypeScript in `convex/` at the repo root, whose
queries are subscriptions, and whose mutations are serializable transactions. It replaced Jazz v2
(`2026-09-jazz.md`) in September 2026. Nothing of Jazz survives but what it taught; the Coach's
quizzes come back through the Import box. The move was also an evaluation, and its verdict is in
`../database-decisions.md` (*Verdict*): keep Convex.

**Turso stays out; Drizzle does not return.** Convex's documents and indexes are the whole data
layer.

**This is the stack's four-way test applied, not an exception to it.** Convex is stable, widely
used for AI-coded apps, and publishes its own rules for agents (`convex/_generated/ai/guidelines.md`,
which this project's rules override where they collide: see *Rules that follow*).

## The shape of the data

* **Rows, as under Jazz, but read and written on the server.** A view dispatches an action;
  `hunts.perform` (one mutation, one transaction) validates it, reads what it needs by index and
  writes the rows it comes to. Views subscribe to query functions that assemble what a screen
  shows (`hunts.open`, `quizzes.open`, `reviews.forQuiz`, `idents.current`, `hunts.list`). A
  quiz "document" (the formula bag, the export, the git mirror's file) is still a projection
  assembled from rows (`quizFrom` in `lib/rows.ts`), now inside a query.
* **One schema source.** The Zod row validators in `models/` are the source; `convex/schema.ts`
  derives every table from them through `convex-helpers/server/zod4` (`zodOutputToConvexFields`,
  or `zodOutputToConvex` for a table that is a union). What the bridge carries: shape,
  nullability, closed sets, nested objects and arrays, discriminated unions, `zid` relations. What
  stays the row validator's alone: patterns, lengths, integers, cross-field checks. One field is
  written by hand (a botting's `response`, any JSON, whose recursive type TypeScript cannot
  follow through the bridge). `tests/convex/schema.test.ts` is the canary that holds the two
  together; the old coherence test between two authored copies is gone with the second copy.
* **Nullable, never optional.** A stored document carries every field; the patch pattern's
  absent / null / value keep their three meanings.
* **Structured values are ordinary fields.** No JSON text, no transforms: `bulk_ishes_last`,
  `last_sortkey`, `items` and `response` are plain fields.
* **Widgets are a tagged union** (`kind: 'expressing' | 'botting'`), each kind with its own fields
  and no nulls for the other's, which Jazz's alpha could not store.
* **Ids are internal and spelled `_id`**, from the row to the tree types (`QuizT`, `QuestionT`,
  `RealmT`, `HuntT`, `IdentT`). Our own fields never start with `_`. Refer by label everywhere
  the outside world sees; `lib/ids.ts` still mints a UUID for a tree node not yet written.
* **A botting is its row.** A cell's history is the newest botting and the newest that answered,
  read by one index walk per cell; `_creationTime` is when it was asked.
* **Children have caps**, in `lib/vv/patterns.ts`: every read of a parent's children takes the
  cap, and every write that would pass it is refused, so a read never silently drops a row.
* **Merge is per field, last writer wins**, as under Jazz: an update writes only the fields that
  changed.

## Validation

Zod validates **every function's arguments** (`zCustomQuery` / `zCustomMutation` with our
schemas), and **every row before it is written** (the row validator, whole, as the row would
stand). Nothing validates rows read back: a query that returns documents declares no `returns`.
Convex's own schema validation on write is the second net, never the message an author sees.

The difference from Jazz is where the first net runs: a mutation is a chokepoint on the server
that a client cannot skip. A refusal travels as a `ConvexError` whose data is `{ failurekind,
message }` (`lib/refusals.ts`), and the browser shows its sentence (`noticeOf`).

## Rules that follow from it

* **Read `convex/_generated/ai/guidelines.md` before working in `convex/`**, and work from the
  installed source, not recall. Where it and this project differ, this project wins:
  `import { v as CVX }`, never `v` (eslint enforces it); no `returns` on a query that hands back
  documents; tests in `tests/convex/`; reads bounded by our caps rather than a bare `.take(n)`.
* **Module names under `convex/` are snake_case**: Convex refuses a hyphen in a module path.
* **Every read goes through an index**, and a parent's children through the parent's index, in
  committed order (`by_quiz_id_and_position`).
* **One subscription per screen-level thing, joined on the server, props below.** Never a query
  per row or per cell. The Export box reads the whole hunt once, when asked, never subscribed.
* **Mutations read the truth, then write.** Jazz's "write from the rows on screen" was a
  local-first workaround; a mutation reads inside its transaction, and optimistic concurrency
  answers the race.
* **Labels that must be globally unique are enforced in the transaction** (idents, hunts).
* **Authorization lives in `convex/authorize.ts`**, and only there. Wide open for the trial.
* **`convex/_generated/` is committed**, marked `-diff`; a push regenerates it, and CI fails on
  drift. A large regeneration goes in a commit of its own.
* **No migrations.** A schema push validates every document and refuses if one no longer fits.
  A local backend is emptied (`scripts/convex_reset`) and pushed again; production is a Coach's
  call. See `../deploy.md`.
* **A local backend per role** (`scripts/convex_backend <dev|agent|e2e|e2e-agent>`, the CLI's own
  binary, 34xx/35xx), so the human's, the agents' and the e2e suite's never share data. Local
  backends need no account and draw on no quota.
* **Don't throw from a query the page depends on**: `useQuery` throws a query's error into React.
  Keep an argument a query would refuse from reaching it.
* **Assert with retries**, as before: a change lands one round trip after it is made.

## Identity: a browser key now, Convex Auth next

For the trial, a browser is identified by a **browser key**: a UUID minted once into
`localStorage` (`state/browser-key.ts`) and passed as an argument to the functions that read or
write its identing. It authorizes nothing, knowingly against Convex's rule about user ids as
arguments, because nothing is authorized in the wide-open trial. The ident gate, idents and
identings work as they did under Jazz; an **identing** is now one browser taking on one ident.

What Jazz's local-first account gave and the key does not: a signed, verifiable root, and a door
to a second device (`exportLocalFirstSecret`). The identity plan, after the playtesting phases,
starts from this brief: Convex Auth's anonymous provider in place of the browser key, Google
behind it, weighed against a hosted hub (Clerk or WorkOS) whose JWTs Convex trusts; client-side
only; with the "anonymous on one device, signed in on another" collision designed rather than
discovered. `authorize.ts`'s rules keep their shape and change their first line.

## What it replaced

Jazz: `src/db/` whole (schema, permissions, JSON-text columns, sync settings, runtime assets,
migrations), `withJazz` in `next.config.ts`, the `jazz_*` scripts, the `migrations` CI job, the
`jazz` skill and `public/jazz/`. The browser-side assembly of a hunt (`useHeldRows`, `useKept`,
the flat per-table reads) and `transact`. The ask route and the bots route stayed as they were.

## Learned in the move (Sept 2026, `convex` 1.46.0)

The detail, phase by phase, is in `whiteboard/convex_yay-progress.md` (*Discoveries*). In short:

* **A local or anonymous deployment does not isolate**: it is one per checkout. The CLI's own
  backend binary, one per role, does; four small scripts run it.
* **`convex codegen` needs a running deployment**, and against an unreachable one writes an
  untyped stub and exits 1. CI's drift check pushes to a backend of its own.
* **The bridge converts every row validator we have**, bar one recursive type TypeScript cannot
  follow, and derives union tables. Zod runs inside Convex's bundle, patched and with our error
  map.
* **A Zod object in the arguments is strict at Convex's door**: Convex validates with the derived
  validator before Zod runs, and refuses a field it does not name where Zod would strip it.
* **`ctx.db.get`, `patch`, `replace` and `delete` take the table name first** in current Convex.
* **`_creationTime` carries a fraction**; the tree's timestamps are whole milliseconds.
* **A mutation's promise resolves once the client's subscriptions reflect it**, so it is also
  "the screen is up to date"; and a watch's listeners run before it resolves.
* **The limits that bite are per function** (4096 index ranges, 32,000 documents read); one
  index walk per botting cell keeps a full quiz inside them.
* **A cached query costs no database I/O**: another browser's rerun of the same query is a cache
  hit. **Database I/O is the number that binds** on the free plan, not function calls.
* **The round trip shows only where a test relied on a write landing in the same instant.** The
  e2e suite runs in about a minute, against minutes under Jazz, and stopped flaking.
* **Convex's client runs under Playwright's fake clock** (`e2e/quiz-history.spec.ts`).
* **The CLI rewrites `.env.local`** on every push; the environment's `NEXT_PUBLIC_CONVEX_URL` wins
  over it, so it is harmless.
